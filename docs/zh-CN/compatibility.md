# Cronicle 兼容性

[English](../compatibility.md) | 简体中文

OwlCron 的目标是通过 Go 实现替代 Cronicle，并通过一定程度的兼容支持迁移。当前兼容范围以下文列出的行为为准，不表示所有 API、存储格式和节点协议都可以互换。Go 节点不能加入原版 Node.js 集群，已有客户端、插件和数据迁移需按本文范围验证。

配置和部署见[配置文档](configuration.md)与[部署指南](deployment.md)，可靠性边界见[已知限制](limitations.md)。

## 调度与插件

- 支持定时与按需事件、时区、catch-up、延迟、持久队列、并发限制、重试及成功/失败链。`timing:false/null` 表示按需执行；手动运行可执行禁用事件，禁用的链目标不会入队。
- 插件通过 stdin 接收一行任务 JSON，通过 stdout JSON 行报告进度、完成、结果与链式数据；普通 stdout/stderr 写入日志。非 detached 插件必须显式报告完成，仅以退出码 0 结束不等于插件协议成功。
- 启动命令、工作目录、uid/gid 和环境取自插件配置。事件、API override 和任务参数不能替代插件的执行上下文；参数按插件 schema 校验，hidden 参数取插件定义。
- 参数拆分支持引用与空参数；shell 表达式须显式交给 shell，不承诺原版 `shell-quote` 的全部语法。
- detached 明确拒绝，不提供后台脱离、跨重启继续执行或旧 PID 接管。
- 默认禁止插件 `update_event`。显式启用后仍固定原事件 ID 并校验更新。HTML 报告在服务端净化；不支持任意内联 style、自定义 `sanitize-html` 配置或任意前端 filter 函数。

## API 与前端

- 自带前端已适配 Go API。外部 Cronicle 客户端须单独验证，不能仅替换服务地址。
- `get_schedule` 返回含 schedule、categories、plugins 等字段的全量配置快照，未实现原版该接口的分页 `rows/list` 约定；`get_event` 仅按 ID 查询，不支持原版按 title 查找及附带 queue/jobs 的完整形状。
- 历史列表使用 `rows/list` 分页约定，详情包含 job、complete 和日志 token。部分错误码及 HTTP 授权错误与原版不同，不能依赖原版全部命名错误码。
- JSON 请求正文须为单个对象，顶层字段不能重复。范围选择字段（`id`、`ids`、`category`、`target`）必须使用准确的小写名称。查询参数只能重复相同值；与 JSON 同名时，仅接受相同标量并保留 JSON 类型。值冲突或数组、对象同时出现在查询参数和正文中，会在授权和执行前被拒绝。批量 `ids` 使用 JSON 数组。创建、删除、中止事件，中止单个任务和分类修改接口按 JSON 正文中的选择字段授权，不能仅在查询参数中提供这些字段。这些规则同样适用于 `/v1`；仍支持独立的查询凭据和仅使用查询参数的读取请求。
- 会话/API key、分类和服务器组范围在服务端检查。旧对象及更新或运行后的实际目标都需授权；WebSocket 按接收方过滤并复核凭据。全局 Stats 仍是汇总值。
- 日志 token 绑定单个任务、限时且只读。网页日志采用认证 POST 轮询；未实现原版 Socket.IO 日志 watcher 协议。
- 活动记录使用 Go 引擎自己的字段，不承诺全部 Pixl 活动类型与展示细节一致。

## 存储、历史与日志

- Filesystem、S3、Couchbase、Redis 使用 Go 引擎自己的记录、索引和备份格式。它们不是 Pixl 旧库迁移器，不能假设可直接打开 Cronicle 的已有磁盘库。
- 集群节点须共享支持所需原子更新语义的同一存储 namespace；Filesystem 集群须显式启用 `shared_storage`，且底层文件系统必须满足进程间锁及持久化要求。独立磁盘目录不能构成共享集群存储。
- 历史按任务 ID 幂等写入，保留清理使用持久删除标记协调恢复。清理和保留配置须结合业务需要设置，不应把默认值当成容量规划。
- 日志按 64 KiB 分块，增量上传并记录已提交偏移；读取默认 64 KiB、最大 1 MiB。完整日志需遍历游标或使用流式下载，旧客户端不能再假设一次请求返回全部日志。默认单任务硬上限为 64 MiB。
- 旧 Filesystem/S3 日志保留读取兼容路径；旧 Couchbase 二进制日志及导入 Redis 的旧单块日志需离线迁移。Redis 保留当前分块日志及 owlcron-storage-v1 备份格式；仅支持单实例 Redis 8.4+，不使用 Lua，不支持 Sentinel 或 Cluster。
- 后端故障时，本机 completion spool、日志及通知队列参与恢复；相应目录必须持久保存。强杀前尚未落盘的数据不保证恢复。存储请求超时意味着结果未确认，不能据此认定写入从未提交。

## 集群与故障语义

- 节点使用独立 `/cluster/ws`、默认 WSS、Ed25519 双向挑战认证，可配置 mTLS；浏览器使用 `/ws`。普通任务帧不另做逐消息签名。旧明文或共享密钥节点配置需要迁移；`cluster_allow_insecure` 仅供显式开发测试。
- 主节点权威由共享存储 CAS 租约及其 owner 决定。每帧复核节点登记、角色与连接代次，主从切换采用降级、重连与 fencing，行为不等同于原版遇冲突直接退出。
- 只有经当前所有者认证的入站流量刷新节点活跃性；本机发出状态或仅看到有效共享租约不等于对端网络正常。已撤销的连接不能借排队帧重新获得权限。
- worker 完成结果和日志先持久保存，完成 outbox 重发至主节点确认完整提交；已完整持久化的重复结果可直接确认。此语义不保证派发请求返回后 worker 已启动，也不保证断连时未确认的派发必然自动补发。
- 引擎重启会校验执行标记和内核启动身份，回收可验证的旧插件进程组，将本机中断任务记为失败；不会盲目重跑已有外部副作用的命令。旧活跃 PID 无法验证或平台无法获取所需身份信息时，需要人工核实。
- 稳定任务 ID、历史幂等、租约和 outbox 不能提供业务副作用 exactly-once。插件须自行处理幂等及未确认执行结果。

## 邮件、WebHook 与 HTTP 安全

- SMTP 支持认证、STARTTLS/隐式 TLS、超时及多收件人；邮件与 WebHook 使用持久队列、重试和死信。投递为至少一次，接收端处理成功但确认丢失时可能重复；真实服务的凭据、网络和接收行为仍须部署验证。
- WebHook 默认仅允许 HTTPS 公网目标，私网/HTTP 例外须显式配置；DNS 与实际拨号双重检查，禁止代理和重定向。支持独立 HMAC-SHA256 签名密钥及私有密钥文件，通知和诊断做敏感信息脱敏。旧宽松配置需要迁移。
- 登录和 Basic Auth 共用按 IP/账户的进程内限流及密码验证并发上限；这不是跨节点全局限流。仅信任配置代理的转发头，Cookie 使用一致的 Secure、HttpOnly、SameSite 策略。
- 普通 HTTP API 和日志流分别有时间边界，WebSocket 使用自身生命周期。Go 引擎保留跨来源写请求检查，没有照搬原版关闭防护的设置。


### 分类 API 委派管理

管理员可分别授予用户或 API Key：`create_categories`、`update_categories`、
`delete_categories`，不会同时授予插件、用户、服务器或 API Key 管理权限。
启用 `cat_limit` 时，创建、更新、删除均必须显式指定获准的 `cat_<id>` 分类 ID，
查询参数不能覆盖请求正文的鉴权对象。不启用范围限制时，权限适用于所有分类。
禁止重复创建 ID 或删除仍有事件引用的分类。浏览器管理区仍仅管理员可访问；
委派客户端通过分类 API 操作，也支持 `/v1` 后缀。管理员界面可配置这些权限。

## 浏览器账号与管理流程

账号由管理员通过 **Admin → Users** 创建。登录页的 **Account access help**
说明如何申请账号或重置密码；自助注册继续关闭。邮箱验证和邮件找回密码默认关闭，
管理员可通过[账号邮件策略](configuration.md#账号邮件策略)开启。找回密码要求账号
处于启用状态，且邮箱已经验证。Cronicle 的旧恢复链接不可复用，需要申请新的
OwlCron 链接；未开启邮件找回时，旧入口显示管理员协助恢复说明。已登录用户可以在 **My Account** 中使用
当前密码修改个人资料和密码。管理员可在 **Admin → Users** 重置其他用户的密码。
如果所有管理员均无法登录，请按部署文档中的管理员密码重置流程离线恢复。CLI
会创建或重置管理员，不能用于普通用户的密码重置，因为它会授予管理员权限。

账号接口使用 OwlCron 自身的契约，不能直接替代 Cronicle 的旧邮件流程。
以下接口均通过 POST 接收 JSON 对象，可选用 `/v1` 后缀：

- `/api/user/request_email_verification`：已登录用户提交 `email` 和
  `current_password`，确认前保留当前邮箱。
- `/api/user/verify_email`：提交验证链接中的 `user_id` 和 `token`。
- `/api/user/forgot_password`：提交准确、区分大小写的 `username` 和已验证的
  `email`；响应不会透露账号是否匹配。
- `/api/user/reset_password`：提交 `user_id`、`token`、`new_password` 和
  `confirm_password`。成功后旧会话和账号链接失效。

这四个接口只有在启用账号邮件后才可用。处理器拒绝超过 4 KiB 的请求体、重复或
未知字段以及非 POST 方法；接受现有客户端作为传输字段附带的字符串 `session_id`，
但它不能替代当前密码或链接令牌。GET 请求不会消费这些令牌。

管理界面会保存插件执行身份和 API Key 启用状态。后端没有提供欢迎邮件、API Key
描述和作者字段，因此表单不再提供这些选项。初始账号密码应通过安全渠道交付。
脚本插件通过 `owlcron-script` 运行经过审阅的文件；默认没有可编写内联脚本的
Shell Plugin。具体配置见[脚本文件](script-files.md)。

服务器组表达式由 Go 正则引擎校验。浏览器保留大小写规则预览常见表达式；无法
预览的表达式明确标为由服务端匹配。添加工作节点前，需要配置共享存储和可信
节点身份。

任务表单可编辑单个成功或失败链目标。通过 API 配置为目标数组的任务会显示并
保留原数组，需要通过任务 API 修改；保存其他字段不会清空这些目标。活动日志
按当前嵌套记录格式显示，并使用完整记录数分页；没有操作者信息的记录不会
虚构用户身份。
