# 版本和发行

[English](../releases.md) | 简体中文

## 支持的工具链和平台

项目支持且 CI 验证的构建系列为 Go 1.27。使用 Go 1.27.3 或该系列更新的安全
补丁版本。`go.mod` 中的 `go 1.26.0` 是模块语言基线，不代表承诺支持或测试
Go 1.26。单独的 `toolchain go1.27.3` 在允许自动选择工具链时指定推荐编译器。
Go 1.25 和 1.26 不属于受支持矩阵。前端和发行构建使用 Bun 1.4.2、
Python 3.9 或以上版本及 make。

发行工作流在原生运行器上构建并运行 Linux amd64 二进制。打包脚本也能验证
开发者本机产物，例如 macOS arm64，但不因此扩大发布支持矩阵。脚本拒绝交叉
编译，因为验证步骤无法运行生成的目标二进制。只有补齐原生构建和运行检查后，
才应声明支持新平台。

## 首版范围

首版面向单节点部署，保留熟悉的 Cronicle 页面和操作流程。运行一个独立的
OwlCron 节点，验证自己的任务和权限，并核对[兼容边界](compatibility.md)。
集群发现、故障转移和远程派发仍为实验能力，不属于初始兼容范围。
这不是 Cronicle 数据或集群的原地升级；先使用[迁移预检](migration.md)，
再人工重建经过审查的配置、凭据、插件和任务。

## 构建并验证本地发行包

安装受支持的工具链后，在仓库根目录执行：

```sh
make release VERSION=v0.0.0-dev
python3 tools/verify_release.py dist/*.tar.gz
```

打包程序将已提交的 `HEAD` 导出到全新的临时源码目录，在其中安装锁定版本的
前端依赖，并仅构建该快照。本地配置修改、未跟踪文件和忽略文件不会进入发行包。
发行前须先提交目标修改；压缩包不会包含未提交内容。

压缩包包含引擎、脚本适配器、Echo Plugin、完整前端资源、示例配置、安装说明
以及完整许可证目录。产物不依赖源码目录或 node_modules。`BUILD.json` 记录
版本、源码提交、构建目标和工具链；`owlcron-engine version` 显示版本和源码提交。
版本命令不读取配置，也不创建运行时文件。一些 Cronicle 兼容响应保留上游协议
版本；识别 OwlCron 发行版本时应使用 CLI 和 `BUILD.json`。

相邻的 `.tar.gz.sha256` 文件可由 Linux 的 `sha256sum --check` 验证。验证命令
检查摘要，将产物解压到临时目录，验证可执行文件元数据及适配器，再仅对解压后
的发行包执行单节点验收。验收覆盖构建后的前端、首次启动和登录、使用内置脚本
适配器的真实任务、历史和日志、保留状态的正常重启，以及停机备份、导入到全新
存储并再次成功执行任务。导出和导入前都会停止服务。恢复前删除原始数据、日志和队列目录，并核对两次
历史任务及其持久化日志内容。存储导出包含已持久化的任务日志，但不包含配置、
脚本文件和独立的本地日志文件，这些内容需要单独保存。

验收程序从源码目录使用 Python 标准库运行；服务及其子插件在源码目录之外运行，
可执行文件 `PATH` 为空，不依赖 Go、Bun、Node.js 或 `node_modules`。
验收脚本需要 `/bin/sh`，生产环境的自定义插件可能还需要各自的解释器和依赖。
此检查验证与构建工具的隔离，不代表已验证容器镜像或所有目标操作系统。

摘要用于检查完整性，不是签名或独立的来源
认证。输出目录中不得已有同名压缩包。压缩包和摘要完整写入临时文件后才生成
最终文件名。检查在 Python 优化模式下仍然有效；所有不安全路径和链接都会在
解包或执行任何内容前被拒绝。

## 维护者发行流程

版本标签采用 `vMAJOR.MINOR.PATCH`，可附加预发行后缀。在宣布稳定的 1.0 政策前，
API、持久化数据和配置仍可能变化；应备份并验证升级及回滚。版本号本身不承诺
自动数据回滚。

1. 合并已审查的修改，确认 CI 通过，并检查中英文文档及第三方声明。
2. 维护者为该审查后的提交明确创建并推送带注释版本标签。普通分支推送不会发行。
3. [发行工作流](../../.github/workflows/release.yml)构建原生 Linux amd64 压缩包，
   检查摘要和解压后运行行为，然后创建附有压缩包及摘要的 GitHub **发行草稿**。
4. 检查草稿说明和附件，验证目标部署及恢复流程，准备好后手动发布草稿。
   不要移动已经发布的标签。

影响打包的 PR 和手动运行只验证 `v0.0.0-dev` 产物，不创建发行草稿。
只有创建草稿的任务具有仓库写权限，构建和验证任务仅有读取权限。工作流暂不
添加签名、SBOM 或来源证明，也不保证压缩包逐字节可复现。
