# 运维与指标

[English](../operations.md) | 简体中文

## 使用专用身份采集指标

`GET /api/app/metrics` 和 `/api/app/metrics/v1` 输出 Prometheus 文本格式
0.0.4；配置了 `base_path` 时需加上前缀。端点要求认证，支持通过 `X-API-Key`
传递 API Key、现有会话或 HTTPS Basic 认证。为专用采集身份只授予
**View Operational Metrics**（`view_metrics`）；管理员也可以访问。
该权限允许查看不受分类限制的节点汇总计数，但不授予任务修改权限。
缺少或无效凭据返回 HTTP 401，权限不足返回 403，不支持的请求方法返回 405。
按正常应用凭据流程轮换和撤销采集凭据；不要将密钥放进 URL、仪表盘或日志。

例如，创建只拥有 `view_metrics` 的专用用户，在采集端配置受保护的密码文件：

```yaml
scrape_configs:
  - job_name: owlcron
    scheme: https
    metrics_path: /api/app/metrics
    basic_auth:
      username: owlcron-metrics
      password_file: /run/secrets/owlcron-metrics-password
    static_configs:
      - targets: [cron.example.com]
```

仅允许可信网络采集，验证 HTTPS 证书，并直接采集每个节点，而不是通过负载均衡
服务访问。可从 30 秒间隔开始。身份认证会读取现有凭据存储；指标采集本身仅读取
内存，不列出存储记录，也不扫描本地暂存文件。

## 理解各项指标

七项指标均为没有应用标签的 gauge。不会包含任务 ID、主机名、用户、命令、
令牌或事件参数。

- `owlcron_role_master`：节点本地的主节点标志，且本地租约未到期。
  它不是重新读取共享存储后对唯一所有权的证明。
- `owlcron_role_worker`：节点本地的工作节点标志。角色切换期间，两项角色指标
  都可能为零；不能通过对工作节点标志取反来判断主节点。
- `owlcron_scheduler_enabled`：本地状态快照中的调度开关。
- `owlcron_jobs_active`：本节点活动任务表中非 pending 条目的数量。
  主节点的表可能包含远程任务，因此它不是操作系统进程数。
- `owlcron_jobs_pending`：同一任务表中的 pending 条目，包括延迟启动或重试。
  不要把主节点和工作节点计数相加后当作唯一任务数。
- `owlcron_internal_queue_tasks`：内存中的延迟队列任务数，不是持久化事件队列
  深度，也不是通知或完成确认发件箱数量。
- `owlcron_shutdown_requested`：节点已收到关闭或重启请求。

任务表字段在同一把锁下获取，内部队列深度单独采样；这些值是运维快照，不是
跨节点事务。目前没有导出权威持久队列深度、发件箱年龄、调度延迟、存储错误率、
磁盘空间或备份新鲜度指标。缺失不代表零值。在增加有界采集机制前，请使用系统、
存储监控和应用日志观察这些来源。

## 告警与处理

采集端 `up == 0` 持续超过两分钟应告警。先检查网络、TLS 信任、凭据过期或撤销
以及 HTTP 401/403，再决定是否重启节点。监控所有预期目标，不能从剩余节点的
指标推断一个工作节点是否丢失。预期只有一个主节点的集群，如果
`owlcron_role_master` 总和持续为零或大于一，应检查租约、网络和节点日志；
不能据此强制启动两个主节点。

结合工作负载基线观察 pending 任务和内部延迟任务趋势。持续积压时检查工作节点
可用性、并发限制、长任务和重试错误。活动任务数增加本身不是终止任务的理由。
任务已完成但历史或通知延迟时，检查完成提交和通知重试日志。干预前记录故障现象
与时间，事故资料中须遮盖凭据及敏感任务输出。

通过外部监控观察数据、日志和队列卷的可用字节与 inode。空间不足时暂停新调度，
保留持久队列，检查保留策略和异常大日志。不要删除队列、历史、事务或租约文件来
腾空间。扩容或在备份受影响数据后执行文档中的保留策略；恢复调度前验证恢复状态
及积压任务。

存储出错时检查服务健康、TLS、访问策略、配额、网络和延迟，区分认证失败、超时
和冲突重试。不要通过切换到空命名空间或同时重启所有节点来消除错误。
[已知限制](limitations.md)中的远程派发和恢复边界仍然存在；这些指标不能证明
任务恰好执行一次。

由备份系统记录成功状态与备份年龄，并定期执行隔离恢复演练。停机要求、备份范围、导入行为和验证步骤统一见[部署与回滚流程](deployment.md#备份升级与回滚)。

### 验证账号邮箱

启用账号邮件功能后，在 **My Account** 填写目标邮箱和当前密码，点击
**Send verification email**。明确确认邮件链接后，新邮箱才会生效；此前原邮箱保持有效。
保存其他个人资料不会应用待验证邮箱，已有邮箱也不会自动视为已验证。
管理员编辑邮箱同样不能绕过验证，创建账号仍由管理员操作。

仅打开邮件链接不会消费一次性令牌，需要在确认页面明确确认。
链接过期或已使用时，请回到 My Account 重新申请。自助注册仍保持关闭。

## 账号邮件与密码找回

公开注册继续关闭。开启 `account_email_enabled` 前，先按[账号邮件策略](configuration.md#账号邮件策略)
配置可信的 HTTPS `base_app_url`（路径匹配 `base_path`）、明确的 `smtp_hostname`、
SMTP TLS 和 `email_from`。生产环境保持 `account_email_allow_insecure` 为 false，
先用专用测试账号验证投递。既有和导入的邮箱初始均未验证；无法登录的用户需要先由
管理员协助恢复，再登录并验证邮箱。

邮箱验证后，在登录页选择 **Forgot Password?**，填写准确的用户名和已验证邮箱。
不存在、禁用、未验证和匹配的账号均返回相同提示，成功响应不代表邮件已投递。
打开邮件链接，输入并确认新密码（12–72 个 UTF-8 字节），明确点击 **Reset Password**。
旧 HTTP/WebSocket 会话和未消费的账号链接随后失效，需要使用新密码重新登录。
找回流程不会创建或启用账号，也不会改变权限。

链接默认 30 分钟过期，可通过 `account_token_ttl_seconds` 调整；同类操作重新申请后，
旧链接失效。仅打开链接不会修改账号。浏览器在加载应用资源前从地址栏清除令牌，
刷新会丢失内存中的令牌，需要重新打开原邮件。不要把链接复制到日志、工单或截图。
接口仅通过 POST 消费令牌，GET 请求不会修改账号，Cronicle 的旧恢复链接不可复用。

修改邮箱、修改密码、禁用或删除账号、轮换 `secret_key` 均会撤销待消费链接。修改
邮箱必须输入当前密码并验证新地址，在完成之前仍保留旧地址。邮箱变更通知发往旧
地址，密码变更通知发往恢复地址；通知在账号修改完成后尽力投递，通知失败不会
回滚已完成的账号变更。

请求受进程内 IP/账号限流和持久化的单用户冷却限制，多节点部署需要额外的共享
入口限流。持久化邮件队列保存账号操作引用，不保存可复用的重置令牌；实际投递前
再次检查有效期和撤销状态。SMTP 失败按普通通知策略重试，重试时间可能超过链接
有效期，此时会丢弃过期或撤销的邮件。未收到邮件时检查 SMTP 连通性、TLS、发件人
策略和通知错误，等待冷却后申请新链接。存储或队列故障也可能阻止投递，不能把
通用成功提示当作邮件已送达的凭据。

备份中的账号操作状态属于敏感数据。恢复时隔离环境并关闭真实收件人，在对外
服务前轮换恢复环境的 `secret_key`，避免历史链接恢复有效；这也会使现有签名凭据
失效。保留离线管理员恢复操作，作为邮件不可用时的后备方案。
