# 不可变任务日志格式

[English](../job-log-format.md) | 简体中文

本文描述 `JobLogRepository` 实现的存储协议。日志服务显式组合原子元数据存储与独立
对象存储。格式实现不会自动启用现有部署；运行时配置、初始化和完整备份能力就绪后，
才能启用 v2 写入。

## 兼容性与归属

逻辑元数据 key 仍为 `job_log_manifest/<base64url-job-id>`。没有 `format` 或
`format: 1` 时使用现有分块格式；`format: 2` 使用不可变格式；未知版本直接拒绝。
只有清单不存在时才允许读取旧单对象日志。v2 根引用的对象缺失或损坏时返回完整性
错误，不能返回空日志或回退到旧对象。

新代码可以读取多种格式，但访问 v2 命名空间的所有写入者必须理解 v2。旧二进制不会
识别存储布局版本标记，必须通过部署配置、凭据和存储命名空间隔离。新的 v2 日志 ID
最多 180 字节，以保证规范 base64url 编码能够放入文件系统对象路径分量。

## 有界的数据表示

| 结构 | 上限 |
| --- | --- |
| 逻辑内容块 | 64 KiB |
| 单次追加 | 64 KiB |
| 单个索引页 | 128 个块引用，编码后 64 KiB |
| 日志大小 | 1 GiB |
| 当前根 | 128 个页引用，编码后 32 KiB |
| Pending 追加计划 | 最多两个内容块和两个索引页 |
| 单次范围读取 | 请求内容最多 1 MiB |

元数据存储为每份日志保存一个可变根。不可变内容块版本和不可变索引页都保存在对象
存储。扩展未填满的尾块时创建新对象，不覆盖旧尾块；只复制受影响的索引页。当前
元数据大小随日志大小变化，不随追加次数增长。旧物理版本仍占用空间，直到 GC 回收。

根保存命名空间、incarnation、存储 ID、已提交位置、final/deleted 标记、页引用、
`commit_seq`、`issued_seq` 和可选的 Pending 计划。每个引用包含长度和 SHA-256。
索引页包含 incarnation、页号和相对块引用，不包含物理 Bucket、命名空间或存储配置。

对象 key 格式为：

```text
<namespace>/logs/<base64url-job-id>/<incarnation>/<upload-seq>-<kind>-<nonce>
```

序号为补零后的 20 位无符号整数；kind 为内容块 `c` 或索引页 `p`；incarnation 和
nonce 均为 16 个随机字节的小写十六进制编码。新预留不会复用旧对象 ID。同一预留的
重试使用完全相同的字节和 ID。这是应用协议保证的不可变性，不是存储侧 WORM 保证。

## 发布协议

1. 读取根和受影响页，校验旧尾块。在原子更新回调之外冻结输入、生成替代块和页，
   分配全部对象 ID。
2. 原子校验已提交根，增加 `issued_seq` 并登记完整 Pending 计划。该操作成功，或
   通过读取根确认不明确的结果之后，才能执行对象 PUT。
3. 先上传内容块，再上传索引页，全部使用普通 PUT。重试时已有对象的实际长度和
   SHA-256 必须一致。PUT 响应丢失时通过有界 GET 核对，仅比较 HEAD 长度不够。
4. 原子校验 Pending attempt 和基准提交序号，发布页引用和新位置，清空 Pending，
   增加 `commit_seq`。

第 4 步是唯一可见性提交点。协议不需要跨存储事务或每次追加的 journal。Pending
保存恢复计划，包含归属和序号的对象 key 用于识别后续垃圾。原子更新回调可能重复
执行，不能进行外部 I/O 或重新分配身份。

相同范围和内容的重试恢复原计划。实时上传以 `final: false` 预留后，进程可能已经
完成；恢复上传时仍保留原计划的 final 意图，完成路径随后通过空追加封口。已经封口
的根拒绝新内容。重试已提交字节时，必须比较真实内容后才能返回成功。

元数据写入成功后仍可能返回错误。应重新读取根确认是否已经发布。确认信息不可用时，
不能删除已上传对象，也不能替换仍有效的预留。

## 删除和回收

逻辑删除原子设置 `deleted` 和 `final`，清空 Pending 和当前页引用，永久保留
incarnation 与最高上传序号。现有任务级删除流程继续管理自身的删除标记。到期的
Pending 必须通过原子根更新撤销，截止时间本身不授权删除对象。

每个 owner 的回收先读取完整根快照，记录水位线 `H = issued_seq`。完整标记当前
索引页及其引用的内容块，再标记 Pending 分配的所有对象，包括尚未上传的对象。
只删除同一 incarnation 下序号不超过 H 且未被标记的对象。之后的新预留序号更大，
不会被本轮删除。

安全性要求：已退休引用不能重新发布；全部新引用在 PUT 前登记；同一命名空间和
incarnation 的序号历史不能回退。当前协议不支持内容去重或恢复旧索引页来回滚日志。
备份应恢复到新的命名空间。

回收使用有界对象库存分页，不把元数据 key 全部加载到内存。库存不是快照。游标可能
过期，遇到 `blob.ErrInvalidCursor` 应从头重新扫描。某个 owner 标记失败时，保留
返回的下一页游标：跳过该 owner 的删除，让其他 owner 继续推进，后续完整扫描会
重试失败项。根或页读取错误不能被解释为空引用集合。

宽限期减少与读者的竞争。根推进后旧页消失时，范围读取在有限重试预算内改用最新
根；最新根仍引用缺失对象时，读取失败。设置宽限期时，修改时间未知的对象保留。

延迟的 PUT 可能在 DELETE 后完成，留下不可见对象。周期库存扫描会再次回收它，
一次扫描不能承诺物理垃圾永久消失。GC 不会删除整个上传前缀，因为同一次上传可能
同时包含仍在使用的完整块和已经退休的尾块。

## 离线管理与验证

`VisitCommittedObjects` 流式读取并校验当前页和内容块，拒绝 Pending，并检查
访问期间根没有变化。它不是跨日志快照，管理备份必须停止写入者和回收器。重新绑定
根时保留序号和删除屏障，只改变物理命名空间和存储绑定；页内容不变，可以逐字节
复制到新命名空间。

`go test -race ./storage -run '^TestJobLogV2'` 覆盖发布失败、确认响应丢失、并发
写入、小追加、块与页边界、删除和迟到上传、回收与读取竞争、格式保护以及独立命名
空间恢复。真实服务和进程故障验收用于补充协议测试，参见[测试指南](testing.md)。
