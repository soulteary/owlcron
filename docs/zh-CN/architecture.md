# 架构

[English](../architecture.md) | 简体中文

本文说明当前实现中的职责分工、持久化边界和恢复流程。部署时还需阅读[已知限制](limitations.md)；有恢复机制不代表可以省略备份或业务幂等处理。

## 项目与运行组成

Go 模块位于仓库根目录，工具链要求以 [go.mod](../../go.mod) 为准。服务端提供调度、插件执行、HTTP API、WebSocket 和存储访问；浏览器界面构建为静态资源。服务运行不依赖原版 Cronicle 进程，业务插件所需的 shell、Node.js、Python 等运行时由部署方提供。

支持的 Cronicle 行为和迁移要求见[兼容性文档](compatibility.md)。

主要职责如下：

- [入口](../../main.go)：配置、监听端口、进程生命周期和退出状态。
- [Engine](../../engine/engine.go)：节点角色、每秒维护、主节点租约与关闭等待。
- [Scheduler](../../engine/scheduler.go)：事件快照、分钟调度、持久游标、catch-up 和事件队列。
- [JobManager](../../engine/job_manager.go)：目标选择、并发预留、插件进程、资源检查、取消重试及完成归档。
- [Communication](../../engine/communication.go) 与 [节点消息处理](../../engine/websocket_handler.go)：认证连接、心跳、远程派发、完成重放及确认。
- [Storage](../../storage/storage.go)：Filesystem、S3、Couchbase 的记录、列表、原子更新及备份接口。

`Event` 是配置，`Job` 是一次执行的快照，`Plugin` 定义管理员允许执行的程序。队列和远程执行保存准入时的参数，后续事件修改不应替换已接纳任务的执行语义。

## 存储与一致性

Filesystem 使用可取消的进程内锁和跨进程排他文件锁，写入先同步临时文件再原子替换。多记录事务通过持久 redo journal 恢复；读取也参与同一锁，因此吞吐与挂载延迟会影响整个节点。S3 使用条件请求，Couchbase 使用 CAS；后端能力、操作超时及条件冲突必须按错误处理。

主要持久状态包括：

- `events:<id>` 及事件索引：规范配置和可恢复的枚举入口。加载遍历全部分页，记录或分页读取失败时保留原内存快照。
- `global/master_lease`、`global/state`：主节点 owner、租约到期时间及全局状态所属代次。
- `active_jobs`、`global/event_queue/<eventID>`、`queue_admissions:<token>`：活动预留、事件队列快照和稳定任务 ID。
- `jobs:<id>`、`history/completed/<编码 ID>`：任务规范记录和每任务独立历史索引。
- `job_log_manifest/<编码 ID>`、`job_log_chunks/<编码 ID>/…`：日志提交偏移、结束状态及分块正文。
- `remote_completions`：worker 已完成但尚未获主节点确认的信封。
- `notifications/…`、`notification_plans/…`：通知状态和首次确定的投递目标。
- `deleted_jobs:<id>`、日志删除标记、`history_cleanup/…`：删除墓碑及可恢复清理意图。

单 key 原子更新不等于跨 key 事务。任务正文、历史索引、日志、通知和活动预留分步提交，由稳定 ID、完成 spool 和重放修复中间状态。Filesystem 的事务重放也不提供数据库快照隔离。集群依赖各节点访问同一命名空间以及后端正确的原子操作。

## 执行、完成与恢复

任务通过准入检查后预留并发额度，再派发至本机或 worker。插件通过 stdin 接收任务 JSON；stdout 的结构化消息报告进度与结果，普通输出及 stderr 进入日志。明确完成协议、进程退出、取消原因和日志写入错误共同决定最终结果；仅退出成功不代表协议完成。

启动插件前持久保存随机执行标记，进程启动后记录 PID 和内核启动身份。引擎重启时验证身份及标记，再回收可确认归属的遗留进程组，将中断任务归档为失败；不会盲目按旧 PID 杀进程或自动重跑可能已产生外部副作用的命令。无法验证的旧进程需要人工处置，平台权限和进程可见性也会限制自动恢复。见 [进程恢复](../../engine/process_recovery.go)。

完成路径先同步本地 `.completed.json` spool，再提交日志、任务正文、历史索引、通知准入和活动预留移除。后端失败时保留 spool，周期维护及重启再次提交。`log_dir`、`queue_dir` 必须位于持久卷；已写入持久介质之前的内存输出不能承诺在强杀后恢复。

worker 持久保存完成信封后只立即发送该信封；周期和重连重放未确认集合。主节点只有确认完整提交后才 ACK。本进程已确认完成的重复信封直接 ACK，保留首次结果，并清理残留内存活动状态；仅发现共享任务正文已完成，不能跳过其余提交步骤。相关实现见 [完成存储](../../engine/completion_storage.go)、[完成重放](../../engine/state_access.go)。

历史采用每任务独立索引，避免完成时重写全量历史数组。日志按 64 KiB 分块增量上传，读取按窗口或流式发送；上传并发及单任务字节数有上限。配置的历史、日志保留清理按批次执行，保护活动任务和待恢复完成记录。默认保留天数为 0，表示不自动到期；单任务日志限制不等于全节点磁盘配额。见 [分块日志](../../storage/job_logs.go)、[保留清理](../../engine/retention.go)。

## 集群、安全与通知

主节点通过共享原子租约取得独立随机 owner。调度、控制消息和全局状态写入检查当前 owner；全局状态记录代次，防止恢复的旧主覆盖新主状态。这不是 Raft 或多数派共识，依赖后端原子性、共享命名空间和合理时钟。见 [租约](../../engine/leadership.go)、[状态隔离](../../engine/state_fencing.go)。

集群使用独立 `/cluster/ws` 入口，默认要求 WSS，支持专用 CA 与强制客户端证书。Ed25519 节点证明绑定接收方、挑战、角色和租约 owner；节点规范登记、连接身份和当前租约共同约束消息权限。浏览器使用 `/ws`，账户会话不能充当节点身份。

心跳发送按节点最多保留一个待发送任务，并纳入关闭等待；慢连接或远程验证不持有全局 peer 锁。读取空闲超时从等待下一帧开始，不把上一帧的本地处理时间计算为远端静默。通过当前身份及精确租约核验的入站主节点消息刷新存活时间；出站状态不会制造存活信号。超时切换在角色锁内重新核对时间，等待角色锁的消息也重新检查身份及租约，已撤销连接不能恢复权限。

HTTP 侧提供规范账户和密钥检查、对象范围授权、登录及 Basic Auth 限流、可信代理配置、安全 Cookie 和请求超时。WebHook 通过 [http-kit/outbound](https://github.com/soulteary/http-kit/tree/v2.1.0/outbound) 对目的地址和解析结果执行 SSRF 约束，由仓内的[薄适配层](../../engine/webhook_policy.go)转换配置和错误。共享客户端逐次校验请求和实际拨号目标，包括连接复用，并禁用代理和重定向。独立签名密钥及输出、错误脱敏仍由 OwlCron 管理。管理员插件仍可运行任意程序，系统没有不可信代码沙箱。

邮件支持 SMTP 认证、TLS、超时和独立收件人投递。邮件与 WebHook 使用持久队列，具有领取租约、重试、死信和本地 spool；投递携带稳定标识。其语义是至少一次：接收方已接受、发送方尚未持久确认时崩溃，恢复后可能再次投递。接收方应按标识去重，不能承诺外部投递恰好一次。队列依赖三方法存储契约和投递回调，OwlCron 负责 spool、收件人策略和传输。见[投递契约与拆分评估](delivery-queue.md)、[通知队列](../../engine/notification_queue.go)、[邮件传输](../../engine/mail_transport.go)、[WebHook 签名](../../engine/webhook_signing.go)。


账号邮件默认关闭。一次性验证和恢复操作绑定规范用户记录、密码版本、邮箱和有效期，
令牌消费与账号修改通过同一次原子更新完成；用户索引只用于查找。账号邮件队列保存
操作引用，在投递时重新生成并验证链接。密码变更会撤销旧会话。实现见
[账号操作](../../engine/account_actions.go)，使用方法见
[账号操作指南](operations.md#账号邮件与密码找回)。公开注册保持关闭。

压力与故障场景的运行方式见[测试文档](testing.md)。
